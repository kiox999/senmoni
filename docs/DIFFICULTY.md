# 難易度（difficulty）の基準

全問に `difficulty: "easy" | "medium" | "hard"` を付ける。新しく作る問題にも必ず付ける。
UIには表示しない裏設定で、段位認定の出題配分に使う。

| 区分 | 目安 | 例 |
|---|---|---|
| easy | 1ステップで答えられる基本知識。定義・正常値・定番の第一選択・典型像そのままの診断 | 9の法則、GCSの評価項目、典型的な腸重積の検査 |
| medium | 2ステップ。診断したうえで次の検査・治療を選ぶ／典型からやや外れる。標準的な専門医レベル | 臨床像から敗血症性ショックと判断し、次の昇圧薬を選ぶ |
| hard | スコア・分類の計算や閾値、ガイドラインの細かい数値・時間・推奨、例外・禁忌・ピットフォール、紛らわしい鑑別、正解3つ以上の複数解答 | Parkland公式の計算、driving pressure、ベルリン定義、TG18重症度、Kernohan切痕 |

- 配分の目安：easy 3割・medium 5割・hard 2割（科目全体で）
- 迷ったら medium
- 段位認定：hard の割合は `RANKS[].h` で決まる。hard 以外の枠では、5級〜2級は easy を、六段以上は medium を優先して出題する

## 正答率による補正
- Googleログイン中のユーザーが**その問題に初めて答えたとき**の正誤だけを、Firestoreの `qstats/<科目>_<問題ID>` に匿名で集計する（回答数 `n`・正答数 `c`）
- 1人1問1回だけ数える。同時に目印 `qstatBy/<科目>_<問題ID>_<uid>` を作り、`firestore.rules` で二重計上と不正な増分を拒否する
- アプリは回答数30以上の問題の集計を3日に1回取得して端末に保存し（ログイン不要）、段位認定では**ラベルより実際の正答率を優先**する
  - 正答率80%以上 → easy、50%未満 → hard、その間 → medium（`index.html` の `QSTAT_MIN / QSTAT_EASY / QSTAT_HARD`）
- ラベル自体は書き換えない。集計がたまったら、ラベルと正答率が大きくずれている問題を見直す材料にもする

## 手動で固定する
- **アプリから（ふつうはこちら）**：作者アカウントでログインすると、解説画面の下に「作者用：難易度を固定」が出る。易・中・難を押すとその難易度に固定され、「自動」で解除。固定はクラウド（`diffPins/<科目>`）に保存され、全ユーザーの段位認定に反映される
  - 作者の登録は `docs/SYNC_SETUP.md` の「作者用の設定」を参照
- **コードで**：`index.html` の `DIFF_PIN` に書いても固定できる（例：`kyukyu: { 123:'hard' }`）
- 優先順位：`DIFF_PIN` ＞ アプリでの固定 ＞ 正答率（回答30人以上）＞ ラベル

## 付け直しの結果
| 科目 | 問題数 | easy | medium | hard |
|---|---|---|---|---|
| 救急科 | 1212 | 366（30%） | 553（46%） | 293（24%） |
| 小児科 | 1595 | 471（30%） | 810（51%） | 314（20%） |
| 内科 | 2015 | 475（24%） | 955（47%） | 585（29%） |

内科は「専門医らしい」深掘り問題が多いため hard がやや多い。
