# クラウド同期(Googleログイン)のセットアップ

XP・購入した色/音色・成績・復習予定を、Googleアカウントで端末間に引き継ぐ機能です。
**設定ファイル(`firebase-config.js`)が空のあいだは機能が表示されず、従来どおり端末内だけで動きます。**
ホスティングはこれまで通り GitHub Pages のままで、Firebase(無料のSparkプラン)だけを追加します。

## 1. Firebaseの設定(最初の1回・約10分)

1. [Firebaseコンソール](https://console.firebase.google.com/) →「プロジェクトを追加」(Googleアナリティクスは不要)
2. **Authentication** →「始める」→「Sign-in method」→ **Google** を有効化(サポートメールを選ぶ)
3. Authentication →「設定」→「承認済みドメイン」→ **`kiox999.github.io`** を追加
4. **Firestore Database** →「データベースを作成」→ ロケーション `asia-northeast1`(東京)→ 本番環境モード
5. Firestore の「ルール」タブに、このリポジトリの **`firestore.rules`** の中身を貼り付けて「公開」
   (自分のデータ以外は読み書きできないようにする設定です。これを忘れると他人のデータが見えてしまいます)
6. プロジェクトの設定(歯車)→「マイアプリ」→ ウェブ(`</>`)を追加 → 表示される設定値のうち
   `apiKey` `authDomain` `projectId` `appId` の4つを **`firebase-config.js`** に貼る

```js
window.BOARD_FIREBASE = {
  apiKey: "AIza...",
  authDomain: "xxxx.firebaseapp.com",
  projectId: "xxxx",
  appId: "1:123...:web:abc..."
};
```
7. `firebase-config.js` をコミットして push →「Actions」で Pages の反映を待つ → アプリを開き、
   科目一覧の下の「☁ クラウド同期」からログイン

`apiKey` などは**公開されても問題ない値**です(Firebaseの仕様)。守っているのは手順5のルールです。

## 2. 動作のしくみ

- 保存先は Firestore の `users/<自分のID>/state/` に4つ(`global`=XP・購入物・見た目、`naika` `shouni` `kyukyu`=科目ごとの学習データ)。
- ログインしていなくても使えます(端末内保存のまま)。**初めてログインするとき**、端末内のデータをアカウントに統合します。
  すでに別の端末で使っているアカウントなら、XPや解答数は**合算**されます。
- 以降は、解答後しばらくして(約20秒)、画面を閉じる/戻したとき、通信が復帰したときに自動で同期します。
- 端末ごとに稼いだ分は**差分**で足し合わされるので、2台で別々に学習しても、同期を繰り返しても二重に増えません。
- 学習中に他の端末の更新が見つかった場合は、画面下の「反映する」で取り込みます(学習中の画面は勝手に書き換えません)。
- 同期するもの: XP/累計XP・購入物・見た目設定・解答履歴・復習予定・マイリスト（タグと保存した問題・一問一答）・段位と受験履歴・メモのテキスト
- 同期しないもの: **メモに添付した写真**(端末内のみ)、出題設定(演習量や出題順など)、中断中の演習
- 「学習データをすべて消去」は、同期中のアカウントにも伝わります。

## 3. 注意・既知の制約

- **iPhoneの「ホーム画面に追加」から開いたアプリ内でのログイン**は、OSの仕様でポップアップが動かない場合があります。
  その場合は(a) Safariで開いてログインする、(b) パネル内の「引き継ぎコード」で手動移行する、のどちらかで回避できます。実機で確認してください。
- 別のGoogleアカウントでログインすると、「統合する」か「端末のデータを消して復元」かを選ぶ画面が出ます。
- 無料枠(Firestore読み取り5万回/日・書き込み2万回/日)は、個人〜数十人規模なら十分です。

## 4. お問い合わせフォーム

- ハブ画面下の「✉ お問い合わせ・不具合の報告」、設定タブ、各問題の解説画面の「誤りを報告する」から送れます（ログイン不要）。
  問題から送った場合は科目と問題番号が自動で付きます。
- 届いた内容は **Firebaseコンソール → Firestore Database → `inquiries`** で確認します（アプリからは誰も読めません）。
- 項目: `kind`(question=問題・解説の誤り / bug / request / other)・`message`・`contact`(任意の返信先)・`subj`・`qid`・`page`・`ua`・`ver`(ホーム画面アプリかブラウザか)・`uid`(ログイン中のみ)・`createdAt`
- **`firestore.rules` を更新したら、コンソールの「ルール」タブに貼り直して「公開」が必要です**（貼り直すまで送信は失敗します）。
- 連投防止として、同じ端末からは30秒に1件までです。
- **メール通知**: `firebase-config.js` の `BOARD_WEB3FORMS_KEY` に [Web3Forms](https://web3forms.com) のアクセスキー（受信したいアドレスを入力すると届く。公開してよい値）を入れると、送信と同時にメールでも届きます（無料で月250件）。
  返信先にメールアドレスが書かれていれば、届いたメールの「返信」でそのまま返せます。保存とメールのどちらか一方でも成功すれば送信完了と表示します。

## 5. 開発メモ

- 同期のソースは `sync-src/`、配信用にまとめたものが `sync.bundle.js`(自動生成)です。ソースを直したら `npm install && npm run build`。
- テスト: `npm test`(統合ロジックと2端末の同期フロー)。
- `index.html` への追加は3か所だけです(`firebase-config.js` と同期バンドルの読み込み / ハブ画面の `<div id="syncMount">` / 起動処理 `boot()` の同期待ち)。
  `index.html` を別の場所で作り直す場合は、この3か所と、`sw.js` の `FILES` に `firebase-config.js` `sync.bundle.js` を含めることを引き継いでください。

## 5. 問題ごとの正答率（難易度補正）

- ログイン中のユーザーが初めて答えた問題の正誤を `qstats`（集計）と `qstatBy`（1人1回の目印）に記録します。詳細は `docs/DIFFICULTY.md`。
- **このための新しいルールが `firestore.rules` に入っています。コンソールの「ルール」タブに貼り直して「公開」してください**（公開するまでは記録が拒否され、段位認定はラベルどおりの難易度で動きます）。
- 集計は「回答数30以上」の問題だけを読むため、Firestoreが単一フィールドの索引（`qstats.n`）を自動で作ります。追加の設定は不要です。
